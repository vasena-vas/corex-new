# COREX - ТЗ на мобильную адаптацию

Дополняет docs/motion-spec.md. Тексты не меняются - только раскладка, размеры и поведение.
Блок кейсов здесь не описан: его мобильная версия уже задана в docs/motion-spec.md, раздел «Блок кейсов - переключение».

---

## 1. Контрольные ширины

| Ширина | Устройство | Что проверяем |
|---|---|---|
| 360px | узкие Android | ничего не обрезается, нет горизонтального скролла |
| 390px | iPhone 13-16 | основная ширина, всё выглядит задуманно |
| 430px | iPhone Pro Max | крупные элементы не растягиваются |
| 768px | планшет вертикально | промежуточная раскладка |
| 1024px | планшет горизонтально | десктопная раскладка не ломается |

Брейкпоинты в коде: `900px` (планшет → телефон) и `560px` (узкий телефон). Новые брейкпоинты не добавлять без причины.

---

## 2. Глобальные правила

| Правило | Значение |
|---|---|
| Боковые поля контейнера | 20px до 560px, 32px до 900px |
| Горизонтальный скролл страницы | запрещён. Не лечить `overflow-x: hidden` на body, а найти элемент, который вылезает |
| Высота экрана | `100svh` для sticky-сцен, `100dvh` не использовать для pin - он прыгает при появлении адресной строки |
| Заголовки секций | `clamp()`, на 390px не больше 3 строк |
| Основной текст | не меньше 16px, межстрочный 1.5 |
| Моноширинные подписи и эйброу | не меньше 11px |
| Цифры в колонках | `font-variant-numeric: tabular-nums` |
| Зона нажатия | не меньше 44×44px у всех кнопок, вкладок, пунктов FAQ, ссылок в шапке |
| Поля ввода | `font-size: 16px` - иначе iOS зумит страницу при фокусе |
| Ховеры | только внутри `@media (hover: hover)`, иначе на телефоне эффект «залипает» после тапа |
| Длинные слова | `overflow-wrap: anywhere` для email, ссылок, «COREX» в узких местах |
| Нижний отступ у фиксированных элементов | `env(safe-area-inset-bottom)` |

## 3. Движение на телефоне

Система та же, параметры мягче - blur и длинные очереди дорогие на слабых телефонах.

| Токен / приём | Десктоп | До 900px |
|---|---|---|
| `--rise` | 22px | 14px |
| `--blur` | 10px | 4px |
| `--stagger` | 70ms | 50ms |
| Очередь появления | до 6 элементов | до 4, остальные входят вместе с последним |
| Параллакс | до 8% | не больше 2 слоёв, амплитуда вдвое меньше |
| Построчный выезд заголовков | да | да, но строки считаются по фактическому переносу, а не по разметке десктопа |
| IntersectionObserver threshold | 0.18 | 0.1 - на коротком экране блок может никогда не набрать 18% |

Переопределять токены через `@media (max-width: 900px) { :root { ... } }`, а не дублировать анимации.

## 5. Нижняя плавающая кнопка (новое, только телефон)

- Кнопка «Оставить заявку» на всю ширину, прибита к низу экрана с отступом safe-area.
- Появляется после окончания хиро, прячется, когда в зоне видимости форма заявки или футер.
- Появление и скрытие - translateY + opacity, 360ms, `--e-out`.
- Не перекрывает контент: у последней секции нижний padding на высоту кнопки.

## 6. Хиро - панорама

Горизонтальная панорама на узком экране показывает крошечный фрагмент, а текст налезает на иллюстрации. Эффект сохраняем, раскладку меняем.

| Что | Десктоп | До 900px |
|---|---|---|
| Раскладка кадра | текст поверх панорамы | верхние ~55% экрана - станция, нижние ~45% - текст |
| Масштаб панорамы | как сейчас | станция занимает ширину экрана с полями 20px |
| Слои параллакса | 3 | 2 (дальний фон отключить или сделать статичным) |
| Длина дорожки | как сейчас | сократить так, чтобы на одну станцию приходилось примерно 90-100svh прокрутки |
| Высота pin | 100vh | 100svh, значение фиксируется при загрузке и при смене ориентации, не на каждый resize |
| Текст станции | как сейчас | номер «02 / 06» моноширинным, заголовок до 3 строк, абзац до 5 строк |
| Линия маршрута | с подписями станций | без подписей, только узлы и заливка; текущее название уже есть в тексте |
| Вступление (h1, кнопки) | как сейчас | кнопки друг под другом на всю ширину |
| Четыре плашки под хиро | 4 в ряд | сетка 2×2 |

Фоллбэк: при `prefers-reduced-motion` и на ширине меньше 340px - sticky отключается, шесть станций выводятся обычным вертикальным списком с иллюстрацией и текстом.

Проверка: быстрый свайп вниз-вверх не дёргает сцену, адресная строка браузера при появлении не сдвигает текст.

## 7. Блоки ниже

### «Без нас» - ведомость
- Строка ведомости из двух колонок превращается в одну: номер моноширинным слева, под задачей - исполнитель мелким приглушённым текстом.
- Линии между строками остаются, прочерчивание scaleX сохраняется.
- Итоговая строка «→ всё это закрывает один договор» - по левому краю, двойная линия сверху сохраняется.

### SVG-схема «подрядчики против одного договора»
- Горизонтальную схему на телефон не ужимать - текст в SVG станет нечитаемым.
- Сделать отдельную вертикальную версию SVG: подрядчики столбиком, линии сходятся вниз к одному договору.
- Переключение через `<picture>`-логику или два `<svg>` с показом по брейкпоинту.
- Минимальный размер текста в SVG после масштабирования - 12px.

### Сроки
- Две колонки таблиц («Подготовка», «Доставка») - друг под другом.
- Полосы на всю ширину, число справа от полосы в одной строке с названием этапа.
- Шкала полос считается внутри каждой колонки отдельно, как на десктопе.
- Диаграмма параллельности сертификации и производства: подписи над дорожками, не слева от них.

### Калькулятор
- Поля в одну колонку.
- Способ доставки - сегментный переключатель 2×2, а не 4 в ряд.
- Вес и объём: `inputmode="decimal"`, категория и город - нативный select.
- После нажатия «Прикинуть» страница плавно прокручивается к результату, если он ниже видимой области.
- Кнопки «Прикинуть» и «Посчитать точно по моему товару» - на всю ширину.

### Что возим - интерактивный каталог
- Если категории переключаются вкладками - вкладки становятся горизонтальной лентой со scroll-snap, у правого края затемнение-подсказка, что лента листается.
- Активная вкладка автоматически прокручивается в видимую область.
- Карточки в одну колонку.
- Появление «от центра к краям» на одной колонке превращается в обычное сверху вниз.

### Чем это подтверждается
- Одна колонка. Карточка «Своя команда в Китае» первая и визуально крупнее остальных.
- Подпись «Работаем с 2025 года» под блоком.

### Вопросы
- Весь заголовок вопроса - зона нажатия, высота строки не меньше 56px.
- Стрелка справа не сжимает текст вопроса: текст переносится, стрелка остаётся у верхнего края.

### Заявка
- Форма в одну колонку, кнопка на всю ширину.
- Типы полей: имя - `autocomplete="name"`; контакт - обычное текстовое поле без `inputmode`, туда пишут и телефон, и почту, и телеграм; описание товара - textarea от 4 строк.
- При фокусе поле не прячется под клавиатурой: `scroll-margin-bottom` 120px.
- Контакты (телефон, почта, Telegram) - кликабельные `tel:`, `mailto:`, `https://t.me/`.

### Футер
- Одна колонка, всё по левому краю.

## 9. Приёмка

- [ ] На 360, 390, 430px нет горизонтального скролла ни в одном блоке
- [ ] Ни один текст не обрезан и не налезает на соседний элемент
- [ ] Все кнопки и вкладки нажимаются пальцем с первого раза
- [ ] При фокусе в поле iOS не зумит страницу
- [ ] Хиро: адресная строка при появлении не дёргает сцену
- [ ] Хиро: текст станции не перекрывает иллюстрацию
- [ ] Нижняя кнопка не видна в хиро и у формы заявки
- [ ] Ховер-эффекты не залипают после тапа
- [ ] При повторном проходе анимации не переигрываются
- [ ] prefers-reduced-motion: всё содержимое видно
- [ ] Lighthouse Mobile от 80
